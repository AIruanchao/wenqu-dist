## 3. 本域新发现

### 本域新增 P0/P1 发现数：**P0=0，P1=1**

**F-1（P1·高）R9-AUTH-RECEIPT-REUSE-001：签发 receipt 不绑定信封内容，退休 key 存量信封成"变异重签 Oracle"**

- 证据：`auth9_p7_adversarial.log`（rc0，可复现）：
  1. 受管 keyring 正门签发 merge 审批（receipt seq=1 落链）；
  2. 轮换该 key（`retired_receipt_seq` 正常盘点）；
  3. 攻击者（仅持旧 secret，无 keyring 目录写权限）对原信封做变异：`payload.merge_method` squash→merge、`payload.head_sha` 改写、`expires_at` 延寿 1 天，保留 `approval_id/nonce/issued_at/issue_receipt` 四个 receipt 绑定字段，旧 secret 重签；
  4. `reserve_action` 消费**成功**（`action_id=act_5cb53e4c2f78`）；对照 1（全新伪造无 receipt）正确拒；对照 2（原信封再消费）nonce 已被变异件烧掉——反证变异件完成真实消费。
- 放大面：`ApprovalBroker.validate_structure` 对 `expires_at` 只查"晚于 issued_at"，**无消费侧 TTL 时长上限**（`issued 2026-10-01 / expires 2036-10-01` 十年期通过结构校验，`auth9_p7_adversarial.log` 附实测行）——变异件可把任意存量信封延寿到十年级窗口。
- 根因：`IssueReceiptLedger.append` 的 receipt 行只含 `key_id/approval_id/nonce_digest/issued_at`（approval_keys.py:224-227），`issue_receipt_rejection` 只做四元等值绑定（approval_keys.py:1104-1116），信封内容（payload/绑定字段/expires_at）不参与。`reconcile_issuance` 对账只比 `nonce_digest` 不比 `payload_digest`——变异消费落在 `used_ok` 桶，事后对账无检出。
- 影响边界（定级 P1 而非 P0 的理由）：前置条件=旧 secret 泄露+可读一份未消费的合法信封（同原 R8-AUTH-RETIRED-KEY-005 的 secret 窃取前置）；能力严格窄于原 P0（不能凭空新签，只能一次性变异一张存量信封）；高危四类（prod_write/ddl/release/fund_auth）受第二把联签 key 的 HMAC 保护（body 变异使联签失效），低危单签类（resume/risk/merge/rollback）全暴露。但它实质性重开了第八轮 P0-2 收口声明「退休后签的批不能消费」的变异维度，且 receipt regime 的设计目的（不可伪造的时间执法锚）因此不完整。
- 根修建议（最小改动）：receipt 行增加信封体摘要（`sha256(canonical(信封去 signature/cosignatures))` 或至少 `payload_digest+expires_at`），`issue_receipt_rejection` 等值校验；消费侧补 TTL 时长上限（≤30 天，与签发侧 `_MAX_TTL_SECONDS` 对齐）；`reconcile_issuance` 增加 `payload_digest` 对账项。

## 5. 剩余缺口（本域视角）

1. **F-1（新 P1）**：receipt 内容未绑定+消费侧无 TTL 上限（§3）——修后需第十轮独立负向复验（变异重签+十年延寿+对账检出三腿）。

3. 文件型/内存 keyring（fixtures/dev）无 receipt regime（文档化）；`WENQU_KEYRING_DEV_FIXTURES=1` 是显式 dev 正门，生产部署纪律依赖。
4. HMAC 对称认证不提供非否认（既有已知缺口延续）；V3 Ed25519 已为迁移裁定域建立独立非对称通道，approval 域尚未迁移。
5. 飞书签发仍为占位（FeishuApprovalSource NotImplemented，基线 SKIP 1 例）。
6. 高危联签的"两把 key"防共因泄露能力有限：同一 keyring 目录内两把 secret 物理同址（0700 目录为唯一隔离），root/目录写权限攻击者在威胁模型外（文档化）。
