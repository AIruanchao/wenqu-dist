## 6. 第六轮新增实证发现

### F6-AUTH-EXACT-001（P0）— 签名 action payload 未绑定实际 target

独立探针签发 release 审批，payload 精确写入：

```text
release_id=rel-independent-6
artifact_sha256=aaaa...
manifest_sha256=bbbb...
previous_release_id=rel-independent-5
```

随后调用 `reserve_action(..., target="prod://release/UNAUTHORIZED-TARGET-NOT-IN-PAYLOAD")`，系统仍成功 RESERVED→STARTED→COMMITTED，receipt 只与这个事后自选 target 对账。`APPROVAL_CONSUMED` 事件不保留签名 payload，`ACTION_AUTH_RESERVED` 只保存任意 target，重放也无法恢复两者等值关系。

这证明当前只是“存在同类型审批”，不是冻结方案要求的 `valid_exact_action_authorization`。证据：`root/11-independent-probes/auth_exact_target_bypass_probe.{py,log}`。

### F6-BASELINE-DRIFT-001（P0）— 审计目标与运行体在验收中漂移

b259 clean 起点被外部 writer 推进到 07a949，7789 同步变为新 SHA。b259 的 current-runtime 认证不可成立。见第 2.2 节。

### F6-GATE-SCOPE-001（P0）— required、scope 与 coverage 未绑定冻结 manifest

- 仅交 station 0 且省略 `--required`：CLI 以 `{0}` 自举完整集合，rc=0/PASS；
- 显式 station 0、`coverage=1/1`、任意 `scope_hash`：即使权威分母声明为 99，仍 rc=0/PASS；
- 没有 run manifest/planner 的冻结 required 集与 coverage 证据绑定。

这是分母缩水假绿，直接阻断 P0-3。

### F6-GATE-FORMAT-DUP-002（P0/P1）— 镜像并非 Draft-07 全量等价

- 正式 schema+严格 FormatChecker 拒绝纯日期及无时区时间；镜像、Aggregator、CLI 均 rc=0/PASS；
- 同站两份 PASS 的 attempt、scope、coverage、artifact 全不同，只因 outcome/SHA/environment 相同就被记作 `duplicates_ignored=1` 并 PASS；
- 正式 schema 允许的嵌套扩展又被 CLI 私有校验误拒，存在双向不等价。

### F6-SCHEMA-BOUND-001（P0）— PASS 分母等值规则只生成至 64

`station-result-v2.schema.json` 对 1..64 生成等值条件，但整数无对应上限，故 `PASS 65/66` 通过正式 Draft-07。Aggregator 镜像会 BLOCKED，只是补偿，不满足“Schema 自身具备不变量”。

### F6-TRC-GATE-001（P0）— 99/131 不是 required coverage Gate

- 七专属文件全删：dedicated 99→2；trace `--check` rc=0；acceptance 64/64 rc=0；
- DOC-03 测试体置为恒真：专属套件与 trace 均 rc=0，仍计 99；
- acceptance/workflow 根本未运行七文件。

这直接证伪“文件/名字存在即语义实现”和“99 条已形成不可绕过门”。

### F6-TRC-PARSER-002（P1）— trace parser/冻结 SHA fail-open

- 重复相同行、先 poisoned 后正确的重复 ID 行：rc=0；
- `--plan` 指向不存在文件：rc=0/跳过；
- `PLAN_SHA256` 常量没有对方案全文件实算；§20/§25 外修改仍 rc=0；
- 应红输出中 `meta.catalog_integrity` 仍可显示 `OK`。

### F6-EVID-001（P0）— 20 条证据索引未达到严格合同

- 严格合格：0/20；
- 必填值全非空：4/20；

- 裸 hash 与 `evidence_path` 所指具体文件实算一致：1/20；
- 4 条路径只指目录；完整 40hex commit 仅 3/20；
- `repo_head_at_filing=f2b8fc3`，未绑定 b259/CI 37745638008；

### F6-CI-PORT-001（P1）— Ubuntu required acceptance 忽略 `mktemp` 错误

## 12. 剩余整改顺序

1. **冻结唯一 writer epoch**：停止验收期间改源/改运行体；以新 SHA 重新生成 clean archive、CI、制品、运行身份与观察窗，不复用本轮 b259 运行证据。
2. **补 exact action binding**：对每类判别 payload 建立到实际 action descriptor 的规范化等值规则；消费事件持久化 payload digest/授权对象；receipt 必须同时绑定 signed payload 与实际 target。
3. **Gate 必须吃权威 run manifest**：required stations、scope hash、coverage universe、attempt 与 artifact digest 均由冻结 manifest 绑定；省略 manifest/required 一律 ERROR/BLOCKED。
4. **统一 Schema 与生产校验器**：严格 RFC3339；消除 64 上限枚举漏洞；重复站以完整语义/证据身份判等；用差分测试证明与正式 schema 等价。
5. **把 99 专属测试接入 required**：建立 coverage floor/棘轮，删文件、删函数、恒真断言、missing plan、重复 ID 都必须红；不允许方案快照本身充当执行证据。
6. **修 evidence index**：每条绑定 run_id、40hex SHA、environment、scope、ruleset、时间、argv、real_rc、具体文件路径、文件实算 SHA256、fresh_until；禁止目录路径和说明文字 hash。
7. **CI fail-closed**：修 GNU/BSD `mktemp`，启用 `set -euo pipefail`/显式 rc，固定 acceptance 计数口径；加 CODEOWNERS/review、merge_group 与 action commit pin。
8. **完成现役迁移**：以不可变 release/manifest 部署模块化只读 7789；再做真实浏览器、授权写面、回滚和 runtime hash 验收。
9. **从有效样本重启 W9/W10**：样本必须 clean、绑定同一 SHA/CI/制品；shadow 任一端非 200/不可比时采样器必须非零并 `ok=false`；两端可比后才能计第 1 天。
