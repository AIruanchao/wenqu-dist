### 3.2 P0-2：七段骨架真实存在，但关键安全不变量可被打穿

通过项：

- resume 的旧 `expected_state_version` 被拒；

阻断项：

1. **审批不可信：** signature 只验长度，不验签；公共 envelope 的 task/stage/env/scope/policy/ruleset/watermark/state_version 多数字段不是 required，删除后用任意 actor 和伪签名仍可恢复。
2. **判别联合未封闭：** risk payload 混入 resume 字段可通过 Schema 和 Broker，并实际执行 WAITING→RUNNING；`consume()` 不强制 approval_type=resume。
3. **九停客观前置可自报：** `probe_recovered="false"`、`safety_margin_met="false"` 作为非空字符串仍被当真。
4. **绑定可绕过：** 非 40 位 `input_watermark` 会跳过 SHA 比较；错 policy/ruleset 也可在授权路径中被忽略。
5. **CAS 不完整：** 非 resume 的 risk/action authorization 不比较 `expected_state_version`。
6. **双轴错误：** `TIMEOUT + CONDITIONAL` 可映射为 `COMPLETED_CONDITIONAL`；完全不匹配的 HIGH/P1 finding 风险包可被消费并完成 run，违反 P0/P1 不得风险接受。
7. **控制事件可伪造：** 直接调用公共 `EventStore.append` 注入 `RUN_COMPLETED/PASS`，在 S1 仍 RUNNING 时重放即可得到 SUCCEEDED，hash chain 仍显示有效。
8. **attempt 投影不一致：** cancel 活跃 run 后，run=CANCELLED，但当前 attempt 仍 RUNNING。
9. **存在第二正源：** nonce/risk 权威状态在可变 `approval_consumptions` 旁表；仅重放 `pipeline_events` 后，同一 nonce 可再次消费。
10. **自产事件不符合正式 Schema：** WAITING 事件包含 Schema 未声明字段，因 `additionalProperties=false` 被正式 run schema 拒绝。
11. **动作 Saga 缺失：** 未发现 ACTION_AUTH_RESERVED/STARTED/COMMITTED/FAILED_UNKNOWN、control_outbox、外部 receipt/reconcile 等方案 §6.1 链路。

结论：实现不是“仅缺更多测试”，而是当前对抗输入可改变授权、终态和唯一正源语义，属于硬阻断。
